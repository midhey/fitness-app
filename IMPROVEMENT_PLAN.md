# План улучшения мобильного приложения

## Цели

- стабильные 60 FPS на обычных экранах и не ниже 30 FPS на сложных SVG-схемах;
- реакция на нажатие до 100 мс, без записи на диск на каждое нажатие клавиши;
- холодный запуск без белых вспышек и системных панелей другого цвета;
- понятный основной сценарий: открыть день → выполнить занятие → увидеть прогресс;
- сохранение всей функциональности без зависимости от сети.

## P0 — быстрые исправления

Уже сделано:

- фон Android root window и navigation bar приведён к `#0B0D0F`;
- белые системные кнопки и жестовая полоска настроены для тёмной темы;
- состояние записывается в AsyncStorage с debounce 250 мс и принудительным flush при сворачивании;
- анимации приостанавливаются вне активного экрана и ограничены 30 FPS;
- тяжёлый каталог SVG на экране плана создаётся только после нажатия;
- убраны лишние разрешения микрофона и фонового воспроизведения.

## P1 — быстродействие

1. Замерить базовые показатели на слабом Android-устройстве: cold start, JS/UI FPS, память, размер bundle и время открытия каждого экрана.
2. Разбить подписки на store: экран должен получать только используемые поля, а не весь `AppState`.
3. Заменить длинные `ScrollView` со списками истории, упражнений и журнала на виртуализированные `FlatList`/`SectionList`.
4. Подготовить индексы журналов по дате и упражнению, чтобы не фильтровать всю историю при каждом render.
5. Перенести интерполяцию SVG-поз на UI thread либо заранее вычислять 20–30 кадров каждого перехода. React не должен перестраивать всё дерево фигуры каждый кадр.
6. Разделить крупные экраны на `memo`-компоненты: изменение одного подхода не должно перерисовывать всю тренировку.
7. Добавить профилирование release-сборки; результаты debug/Expo Go не использовать как финальную оценку скорости.

Критерий готовности: отсутствие заметных пропусков кадров при прокрутке, вводе подходов и открытой анимации на целевом слабом телефоне.

## P2 — UI/UX

1. Вернуть единый шрифт Onest и настроить шкалу типографики вместо разрозненных размеров.
2. Переделать главную вокруг одного главного действия дня; вторичную аналитику свернуть в компактные блоки.
3. Силовую тренировку показывать пошагово: текущее упражнение, подходы, закреплённый таймер отдыха и свайп к следующему. Полный список оставить как обзор.
4. Для комплексов добавить полноэкранный режим: схема сверху, таймер и единственная крупная кнопка снизу; инструкции раскрывать по запросу.
5. Упростить палитру: один основной accent, отдельные стабильные цвета для кардио и осанки, единые состояния success/warning/danger.
6. Добавить skeleton/loading, полноценные empty states и сообщения об ошибке сохранения.
7. Проверить доступность: Dynamic Type, контраст, TalkBack, зоны нажатия 44–48 dp и режим Reduce Motion.
8. На «Прогрессе» вернуть календарь активности, фильтры периода и понятные подписи графиков.

## P3 — надёжность и функции

1. Экспорт/импорт резервной копии данных и автоматическая проверка версии схемы.
2. Локальные напоминания о тренировках и осанке с настройкой дней и времени.
3. Восстановление активной силовой тренировки и всех таймеров после перезапуска приложения.
4. Unit-тесты расчётов программы и миграций данных; интеграционные тесты начала/завершения занятий.
5. E2E smoke-тесты Android: запуск, вес, силовая, кардио, оба комплекса и восстановление после background.
6. Crash reporting и анонимные performance traces — только с явным согласием пользователя.

## Порядок работ

Сначала P1 и измерения, затем новый пошаговый UX тренировки и комплексов из P2. После стабилизации интерфейса — резервные копии, напоминания и автоматические тесты из P3.
